A codebase remembers what it does.
Cairn remembers what it was promised to do.

Every feature is one stone carrying the user's own words, and one deterministic Playwright proof that the promise is still kept. The registry is plain text, committed next to your code, and CI replays every proof with no model in the loop.

How it works

Two separations do all the work.

Both are enforced mechanically rather than asked for politely. A registry nobody can argue with is the only kind worth committing.

Step 01

The mason extracts the stones.

A raw request becomes draft stones written in the user's language, never in yours. Anything that is not user-observable produces zero stones, and that is a correct outcome, not a failure.

The acceptance lint refuses CSS selectors, HTTP routes, camelCase identifiers, file paths and function calls, with exit code 2.

Step 02

The warden proves them blind.

It never reads the source, the diff or the commit message. It works from the intent, the criteria and the running app in a browser.

A proof written from the code proves that the code does what the code does: a tautology. The coder never sees the proof either: it receives the unsatisfied criterion and a trace.

Step 03

CI replays the proofs, forever.

Once green, the spec is frozen and its sha256 is stamped on the stone. The ratchet , --proven-only, lets a draft be red, but nothing that was ever proven may regress.

--integrity --no-run is a pure audit that catches an agent editing a spec until it passes. No model in the loop, ever.

What is in the box

The registry, the lint, the lineage, the loop.

Three words and no others: the cairn is the registry, a stone is one feature, a proof is the spec that proves it.

A lifecycle, not a checkbox

Five statuses, a frozen state machine, and one rule the whole product rests on: a stone that was ever green may never quietly go back.

draft raised by the mason, lint enforced.
proven the proof is green, lastGreen stamped.
broken a kept promise broke. CI exits 1.
escalated three attempts spent: only a human leaves this status.
retired amended out of the suite. Terminal.

Acceptance criteria the machine polices

User language by construction. The CLI reads the criterion before the registry does, and refuses it with exit code 2 when it smells of implementation.

refused clearCart() empties the cart
accepted emptying the cart from the cart page leaves it with no article

Amended, never edited

An amendment raises a new draft pointing back at the old stone; the old one retires. The lineage of why survives every change.

01KZ4XGH… retired
01KZ7B2M… amends it

An MCP server for agents

Eight frozen tools and three cairn:// resources over stdio. The acceptance guard-rail lives inside the server, where no prompt can argue with it. There is no force.

A review app, not a dashboard

Read the stones, review the drafts, watch the proofs. Keyboard-first, one screen at a time, and one question above all others: do these stones describe what you wanted?

Runs in the browser against a demo cairn: no Rust, no repository required.

Honest scope, v1. Proofs are Playwright specs driving a web app in a browser. If your feature is a CLI, a cron job, a queue consumer or a native app, Cairn has nothing to prove it with yet. The registry, the lint, the lifecycle and the CI ratchet are all runner-agnostic; only the proof format is not. That is a real limit, not a roadmap flourish.
